# 镇海楼值班表自动排班 Skill（duty-roster-generator）

基于「人员花名册 + 历史排班」的确定性自动排班工具：读取最近 N 天实际排班，按权威规则生成未来 3 个工作日（跳过周一）的值班表，每天一个 `.xls`，并做**格式指纹保真校验**，保证输出与空白模板字节级一致。

## 功能特性

- **角色标签驱动**：花名册里 `名字（标签）`，标签是常量锚点（女 / 主持人 / 技术 / 负责人 / 宣传），名字是变量。
- **五类离岗聚合播种**：备注里的 调休 / 请假 / 补休 / 病假 / 年休假 全部解析并聚合进轮转基线，消除"只读调休导致补休者被当从未休过"的冷启动盲区。
- **调休频率自适应**：每天调休人数按历史日均浮动（1–5），非固定 3 人；周二→周日个人轮转，周一永不调休。
- **行政 = 音响同段打包**：行政事务复用同段正堂音响的人（技术+负责人双标签者优先），上午/下午各一人兼两岗，不拆成 3 人。
- **主持人段预算防死锁**：主持人/技术双紧缺时，am 段 distinct 主持人上限 = 可用数 − 1（给 pm 预留），选人优先复用已在 am 段的人——避免开衙缺人或 pm 空岗。
- **段互斥**：每人每天只能落上午段（B/C）或下午段（D）之一。
- **格式指纹保真**：只改白名单格，非白名单格值与格式逐格比对，输出与空白模板 100% 一致。
- **不可行 3 方案**：硬约束无法满足时阻断发布，并给 3 套解决方案（优缺点 / 沟通对象 / 建议话术）。
- **依赖自适配**：脚本优先用仓库内 `.lib/` 自带依赖（xlrd + openpyxl，若存在）；否则回退到 `pip install -r requirements.txt` 安装的包。

## 目录结构

```
duty-roster-generator/
├── SKILL.md                     # 技能文档（权威规则 + 修复记录）
├── scripts/
│   ├── roster_pipeline.py       # 编排主入口（解析→调休→求解→写表→指纹→发布）
│   ├── scheduler.py             # 确定性贪心求解器（硬规则 + 段预算 + 段互斥）
│   ├── io_roster.py             # 花名册 / 历史排班 / 补休解析
│   ├── rest_state.py            # 调休状态播种（五类聚合）+ 轮转
│   ├── template_map.json        # 岗位→单元格映射、打包配对、询问岗配置
│   ├── template_text.py         # 单元格文本渲染
│   ├── write_template.ps1       # Excel COM 写表（Windows）
│   ├── write_template_py.py     # 纯 Python 写表（降级/测试）
│   ├── fingerprint.ps1          # 格式指纹校验（Windows）
│   └── build_blank_template.ps1 # 重建空白模板
├── templates/标准空白值班表.xls  # 空白标准模板（无名字，只留岗位标签）
├── examples/                    # 三种历史版式示例
└── .lib/                        # 可选：自带依赖（xlrd / openpyxl，不入库）
```

## 运行要求

- **Windows + Microsoft Excel（COM，16.0+）**：写 `.xls` 必需；无 Excel 可用 `write_template_py.py` 纯 Python 通道（降级）。
- **Python ≥ 3.9** + 依赖：`pip install -r requirements.txt`（xlrd、openpyxl）。脚本优先用 `.lib/` 自带依赖，否则回退到 pip 安装的包。
- `.ps1` 脚本必须带 UTF-8 BOM（Windows PowerShell 读中文必需，仓库内已带）。

## 快速开始

1. 准备输入（**运行时自备，不入库**）：
   - `输入/人员/人员.xls` —— 花名册，格式 `姓名（标签）（标签）`（或姓名在 A 列、标签在相邻格）。
   - `输入/过往三天/*.xls` —— 历史实际排班（建议 ≥6 天；备注里写清 调休/补休/请假/年休假 名单）。
2. 准备变更（可选）：`changes.json`
   ```json
   {
     "unavailable": [{"name":"张三","date":"2026-08-14","kind":"请假","scope":"day"}],
     "rest":        [{"name":"李四","date":"2026-08-15"}],
     "inquiry":     {"公务讲解": true, "大屏制作": false, "学宫": true}
   }
   ```
   - `unavailable`：请假/休假/病假/年休假/补休（`scope: 上午/下午` 为半天空缺）。
   - `rest`：强制某人某日调休（覆盖自动轮转）。
   - `inquiry`：排前询问岗本轮是否安排（公务讲解/大屏制作/学宫）。
3. 运行：
   ```
   python scripts/roster_pipeline.py <changes.json>
   ```
   不带参数 = 无变更常规排班。
4. 产物在 `输出/<时间戳>/`：3 张日表 + `排班说明与告警.xlsx` + `运行摘要.json`（status / 调休 / 告警 / 指纹结果）。

## 输出

- `输出/<时间戳>/2026-MM-DD值班表.xls` × 3（未来 3 个工作日，跳过周一）
- `排班说明与告警.xlsx`（正常 = 说明；不可行 = 3 套方案）
- `运行摘要.json`（供上层对话读取的机器可读结果）

## 隐私说明

- **真实数据不入库**：`输入/`（花名册、历史排班）、`输出/`（生成的真实排班）、`状态/`（轮转状态）及含真实姓名的分析文档均已加入 `.gitignore`。
- 仓库公开内容仅含：skill 代码、空白模板（无姓名）、示例版式、规则文档。规则文档中的姓名为规则锚点示例，使用时请以自己花名册为准。
