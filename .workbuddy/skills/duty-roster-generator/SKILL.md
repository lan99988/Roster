# 镇海楼值班表自动排班 Skill

## 何时使用
用户贴出凌乱的变更信息（"谁某天休假/请假/病假/年休假/补休"），要求按历史规律排未来 3 天班，每天一个 Excel，放进 `输出/`；或要求"按过往三天规律重排"。

## 核心设计（低 token）
全部解析 / 求解 / 写表 / 校验都在本地脚本完成，对话层只回读 `运行摘要.json`。每次生成消耗极少 token。

## 执行约束（会话纪律）
- **任务未彻底完成前，禁止结束对话**：从排班启动（解析 / 生成 / 校验任一阶段）直到 `运行摘要.json`、全部日表（3 张）、`排班说明与告警.xlsx` 全部产出且核验通过之前，agent 不得提前收尾、不得声称"已完成"。后台任务（如 Excel COM 指纹校验）仍在运行时，必须等待其完成通知，不得在结果未就绪时返回完成态；确有慢速步骤时耐心等待自动通知，完成后立即核验产物（摘要 `status`、格式指纹 `verified`、每日调休与告警），确认无遗漏后再呈现结果。

## 输入
- `输入/人员/人员.xls` —— **唯一权威花名册**（含角色标签，会变动）。名字是变量，标签是常量锚点。两种布局都支持：
  - 现格式：`名字（标签）（标签）` 合并在 A 列
  - 备用格式：名字在 A 列、标签在同行相邻格
- `输入/过往三天/*.xls` —— 历史实际排班（**建议 ≥6 天**：6 天四类离岗聚合可覆盖 84% 名册，配合一轮生成即可 19 人全覆盖；最新 1 个仅作规律参考）。备注里的 调休/请假/补休/病假/年休假 五类离岗都会解析并聚合进轮转基线。
- **已离职人员**：不在 19 人名册的历史人员（如林璜、慧銮）一律忽略，不参与解析与轮转基线（`io_roster.NAME_ALIASES` 已清空——林璜 ≠ 林煌，勿再做别名映射）。
- 用户凌乱文本 —— 由 **agent 在对话中解析**成 `changes` JSON（见下方 schema），**不**由脚本解析。

## 关键文件
| 文件 | 作用 |
|---|---|
| `templates/标准空白值班表.xls` | **空白标准模板**：无名字、只留岗位标签列 + 备注常设条目。每次复制它、只填白名单格，保证所有表格位置永久对齐。改版式后用 `build_blank_template.ps1` 重建。 |
| `状态/rest_state.json` | **调休状态**：每人上次休息日 + 休息历史。跨运行轮转连续性靠它。仅当排班成功且指纹通过才回写。 |
| `scripts/roster_pipeline.py` | 编排主入口：`解析 → 选模板 → 读/排调休 → 求解 → 写表 → 指纹校验 → 发布`。含**调休频率按历史日均浮动**（1–5）。 |
| `scripts/scheduler.py` | 确定性贪心求解（无随机）。11 条硬规则 + **主持人段预算（防 am/pm 单段被抢空死锁）** + 段互斥 + 不可行 3 方案。 |
| `scripts/io_roster.py` | 解析花名册 / 历史排班 / 补休。`_extract_unavailable` 支持**一段多类离岗**（如"瑞琼补休、毓廷请假"）。 |
| `scripts/rest_state.py` | 调休状态 播种（从历史**聚合五类离岗**）+ 轮转（距上次休息间隔最大者优先，关键标签负责人/技术保护）。 |
| `scripts/template_map.json` | 岗位键、匹配标签、白名单单元格、渲染后缀、`pair_with` 打包配对（行政复用同段音响）、**主持人岗 am 优先顺序**、排前询问岗配置、`gate_tail` 闭馆固定说明。 |
| `scripts/template_text.py` | 单元格文本渲染（角色后缀拼接）。 |
| `scripts/write_template.ps1` | Excel COM 复制空白模板 → 写白名单格 → 两遍格式拷回（保真）。 |
| `scripts/fingerprint.ps1` | 严格格式指纹：白名单格只比值，非白名单格比值+格式，保证输出与模板完美一致。 |

## 运行方式
1. Agent 把用户凌乱文本解析为 `changes.json`：
   ```json
   {
     "unavailable": [{"name":"冰娜","date":"2026-08-14","kind":"请假","scope":"day"}],
     "rest":        [{"name":"向荣","date":"2026-08-15"}],
     "inquiry":     {"公务讲解": true, "大屏制作": false, "学宫": true}
   }
   ```
   - `unavailable`：请假/休假/病假/年休假/补休。`scope` 为 `上午`/`下午` 时半天空缺，其他（含 `day`/缺省）按全天。
   - `rest`：用户**强制**某人某日调休（覆盖自动轮转）。
   - `inquiry`：排前询问岗本轮是否安排。`公务讲解/大屏制作/学宫` 三岗，用户备注没说"不需要"时，**每次运行前必须先询问**用户要不要排，再传此字段。
2. 运行（用隔离 venv，已装 xlrd + openpyxl）：
   ```
   <venv>/Scripts/python.exe .workbuddy/skills/duty-roster-generator/scripts/roster_pipeline.py <changes.json>
   ```
   不带参数则 `changes={"unavailable":[],"rest":[]}`（无变更常规排班）。

## 输出
`输出/<时间戳>/`：
- `2026-MM-DD值班表.xls` × 3（未来 3 天，跳过周一）
- `排班说明与告警.xlsx`（正常=说明；不可行=说明 + 3 套方案）
- `运行摘要.json`（status / 每日调休 / 告警 / 指纹验证结果 —— 对话层读它）

## 11 条硬规则（已建模进 scheduler）
1. 女（8 人）→ 游客服务驿站必须女，上午 2 + 下午 2 = 4/日；侨批展邮女优先。
2. 主持人（5 人）→ 每日 distinct ≥ 2，覆盖演艺/开衙/讲解子岗（可同人叠加 ≤3 岗）。**段预算防死锁**：am 段 distinct 主持人上限 = 当日可用主持人 − 1（预留 1 人给 pm 段），选人优先复用已在 am 段的人——避免主持人/技术双紧缺时单段被抢空（如 8.16 休 2 主持人、8.18 技术缺人时开衙/演艺互抢）。
3. 宣传 = 煜波（单人专属，**可选**：当日煜波不可用则留空 + 软告警，不硬阻塞）。
4. 技术（映纯/启辉/兰舟）↔ 正堂音响；负责人（震生/映纯/启辉）↔ 行政事务。**行政事务复用同段正堂音响的人**（上午段音响者兼行政上午、下午段音响者兼行政下午，双标签映纯/启辉优先；同段音响者非负责人时行政单独补一名负责人）。音响岗本身也**双标签优先**（`tags=["技术","负责人"]` 交集 + `fallback=["技术"]` 兰舟兜底）。
5. 门口指引/闸机 = 兜底岗（填无调休无安排者）。
6. 镇海楼/游客服务中心/后闸机 **暂不排**；大屏/公务讲解/学宫 **排前询问**。
7. 周一全员休；每天调休人数按历史日均浮动（1–5），周二→周日个人轮转。播种轮转基线时聚合 调休/请假/补休/病假/年休假 五类离岗（不只调休）。
8. 不可用（请假/休假/补休/调休）者绝不被排班。
9. 每人常规 ≤2 岗/日（主持人岗可叠加至 ≤3）。
10. 负荷均衡：同一次运行内优先摊薄使用次数，再参考历史近 3 天负荷。
11. 输出字节级保真：只改白名单格，其余格式/合并区 100% 继承空白模板（指纹校验强制）。
12. **段互斥（B/C=上午、D=下午）**：每人每天只能落上午段或下午段之一，禁止跨段。
13. **行政事务可选空缺**：负责人（震生/映纯/启辉）排不下时行政上午/下午可留空 + 软告警，不硬阻断（历史有先例：8.13 行政下午空）。

## 已修复的关键问题（历史修复记录，勿回退）
- **调休状态污染**：`rest_state.json` 曾被重跑写入未来日期，`plan_rest` 对负间隔钳为 0 防再选中；修复时删污染状态、从历史重新播种。
- **冷启动盲区**：只播种"调休"导致补休/年休假者被当"从未休过"→ 改为五类离岗聚合（`_seed_from_history` 的 `OFF_KEYS`）。
- **一段多类漏抓**：`_extract_unavailable` 旧实现一段只抓第一个类型 → 按关键词位置切分，正确提取"瑞琼补休、毓廷请假"。
- **别名污染**：`NAME_ALIASES={"林璜":"林煌"}` 是错误配置（林璜≠林煌且已离职）→ 已清空；不在册历史人员一律忽略。
- **行政拆 3 人**：行政事务独立排负责人（震生/启辉/映纯 3 人）→ 改为 `pair_with` 复用同段音响 + 音响双标签优先（2 人打包）。
- **调度死锁**：主持人/技术双紧缺时单段被抢空（开衙缺人或 pm 空岗）→ 主持人岗"全 am 提前"顺序 + 主持人段预算 + 复用优先排序。
- **调休频率硬编码 3**：→ 按历史每日调休人数均值浮动（钳 1–5）。

## 不可行处理
硬约束无法满足（如女员工不足 4 人、主持人不足 2 人、技术/负责人缺口）→ 阻断发布，并在 `排班说明与告警.xlsx` 给 **3 套方案**，每套含：优缺点、沟通对象、建议话术。此时 `输出/` 只出报告，不出日表。

## 排前询问岗
`公务讲解 / 大屏制作 / 学宫` 三岗历史常空。每次运行前若用户备注未声明"不需要"，agent 必须用 AskUserQuestion 问用户本轮是否安排这三岗；答案写入 `inquiry` 字段。确认的岗写入"（待安排·请负责人指派）"占位，未确认的留空。

## 环境
- **Python ≥ 3.9** + 依赖：`pip install -r requirements.txt`（xlrd、openpyxl）。脚本优先用 skill 自带 `.lib/`（若存在），否则回退到 pip 安装的包。
- 写 .xls 依赖本机 **Microsoft Excel COM**（Windows，Excel 16.0+）。无 Excel 环境则无法写出 .xls（可改用 `write_template_py.py` 纯 Python 通道做降级/测试）。
- 所有 `.ps1` 必须带 UTF-8 BOM（Windows PowerShell 读中文字面量必需）。
- 运行入口：`python roster_pipeline.py <changes.json>`（不传参数 = 无变更常规排班）。

## 重建空白模板
若 `人员.xls` 版式或岗位行变化，重跑：
```
powershell -File build_blank_template.ps1 <最新历史xls> <templates/标准空白值班表.xls>
```
